# ShopAgg 插件开发指南

## 1. 运行模型

ShopAgg Plugin API 1.0 是进程内 PHP 插件系统。插件代码与核心共享请求进程和 SQLite 数据库，但通过公开 SDK、事件、过滤器、页面插槽和服务注册表进行组合。正常请求只读取 `storage/cache/plugins.php`，不会扫描插件目录。

最低环境：PHP 8.1、SQLite3。插件不得要求站点安装 Composer；第三方依赖应随 ZIP 放入 `vendor/`。

## 2. 创建插件

```bash
php shopagg plugin:make my-plugin
php shopagg plugin:validate plugin-dev/my-plugin
php shopagg plugin:pack plugin-dev/my-plugin
```

参考可运行插件：`examples/plugins/hello-shopagg`。

插件目录至少包含 `plugin.json` 和 Manifest 中 `autoload.psr4` 指向的源码目录。安装后的 PHP 源码位于受保护的 `storage/plugins/{id}/{version}`，`assets/` 中允许的静态文件会发布到版本化公开目录。

## 3. Manifest

Manifest 的完整机器规范见 `Documents/plugin.schema.json`。常用定义：

```json
{
  "schema_version": 1,
  "id": "member-center",
  "name": "Member Center",
  "vendor": "Example",
  "version": "1.0.0",
  "description": "Front-end member identity provider",
  "requires": {"shopagg": ">=1.3.0", "php": ">=8.1.0"},
  "autoload": {"psr4": {"Example\\Member\\": "src/"}},
  "lifecycle": "Example\\Member\\Plugin",
  "routes": [], "events": {}, "filters": {}, "slots": {},
  "provides_services": {}, "requires_services": {}, "jobs": {}, "settings": {},
  "permissions": [], "admin_menu": [], "dependencies": [], "conflicts": []
}
```

处理器统一写成 `完整类名@方法名`。插件 ID 只能包含小写字母、数字和中间连字符。版本使用 SemVer；依赖约束支持 `=、>、>=、<、<=、^`。

## 4. 路由、请求与响应

```json
{
  "method": "POST",
  "path": "/payment/webhook/:gateway",
  "name": "payment.webhook",
  "handler": "Example\\Payment\\Webhook@handle",
  "middleware": ["webhook"],
  "layout": "standalone"
}
```

处理器签名：

```php
public function handle(Request $request, PluginContext $plugin, string $gateway): Response
{
    $payload = $request->json();
    return Response::json(['ok' => true]);
}
```

中间件：`admin`、`permission:plugin.id.permission`、`csrf`、`member`、`webhook`，也可以声明插件自己的 `Class@method`。响应支持 HTML、JSON、重定向、文件下载和流式输出。`layout: theme` 会把字符串响应放入当前前台主题。

插件可申请一级路由，但不能覆盖核心保留路径或其他已启用插件的同方法、同路径路由。

静态资源放入 `assets/`，并可按路由或主题视图按需加载：

```json
"assets": [
  {"path": "css/account.css", "location": "head", "routes": ["/account*"]},
  {"path": "js/checkout.js", "location": "footer", "routes": ["/checkout*"]}
]
```

## 5. 数据库与迁移

迁移文件放在 `migrations/` 并按文件名排序：

```php
return new class {
    public function up(PluginSchema $schema, PluginContext $plugin): void {
        $schema->create('orders', [
            'id' => 'INTEGER PRIMARY KEY AUTOINCREMENT',
            'number' => 'TEXT NOT NULL UNIQUE',
            'status' => "TEXT NOT NULL DEFAULT 'pending'"
        ], ['status' => ['status']]);
    }
};
```

逻辑表 `orders` 会变成 `p_{plugin_id}_orders`。业务代码通过 `$plugin->database()->table('orders')` 取得真实表名。不要修改核心表或直接读写其他插件表；跨插件协作使用服务接口。

## 6. Event、Filter 与 Slot

```php
$plugin->events()->dispatch('order.paid', $order);
$price = $plugin->filters()->apply('product.price', $price, ['product' => $product]);
$html = $plugin->slots()->render('site.content.after', ['page' => 'product']);
```

Manifest 监听器：

```json
"events": {"order.paid": {"handler": "Example\\Points\\Listener@paid", "priority": 100}}
```

同步监听器应快速完成；网络请求、采集、通知、批量导入和文件转换应提交任务。

## 7. 服务组合

插件通过 `provides_services` 提供标准业务能力；旧字段 `services` 作为兼容别名继续支持：

```json
"provides_services": {
  "payment.gateway": {
    "class": "Example\\Payment\\StripeGateway",
    "provider": "stripe",
    "version": "1.0.0"
  }
}
```

依赖服务使用接口版本约束，系统会在启用前检查：

```json
"requires_services": {
  "member.identity": "^1.0.0",
  "payment.gateway": {"version": "^1.0.0", "provider": "stripe"}
}
```

调用：

```php
$identity = $plugin->services()->get('member.identity');
$gateways = $plugin->services()->all('payment.gateway');
```

单提供者服务：`member.identity`、`order.manager`、`points.manager`、`cart.manager`。多提供者服务：`payment.gateway`、`notification.channel`、`form.type`、`file.converter`、`data.importer`、`data.exporter`、`data.collector`。

标准接口和 DTO 位于 `App\Plugins\Contracts`、`App\Plugins\DTO`。

## 8. 分片任务

```php
final class ImportJob implements ChunkedJobInterface {
    public function handle(JobContext $job, mixed $cursor): JobResult {
        // 处理一批；接近执行预算时返回下一游标
        return $more ? JobResult::continue($nextCursor, $progress) : JobResult::complete();
    }
}

$plugin->jobs()->dispatch('catalog.import', ImportJob::class . '@handle', $payload, $idempotencyKey);
```

任务可由机会式调度、后台“执行任务”、共享主机 Cron URL 或 `php shopagg plugin:jobs` 处理。任务应幂等，并用游标保存进度；停用插件后，其待执行任务不会被调度。后台支持失败任务重试与待执行任务取消，超时锁会自动恢复。

## 9. 后台扩展

`admin_menu` 声明后台入口；`permissions` 声明 Staff 可分配权限；`settings` 声明由核心渲染的插件设置表单。插件自己的写操作路由应同时使用 `admin`、权限和 `csrf` 中间件。

## 10. 开发配方

- 表单：插件数据表 + 前台 GET/POST 路由 + `form.submitted` Event。
- 会员：实现 `MemberIdentityProviderInterface`，提供 `member.identity`，声明 `/login`、`/register`、`/account`。
- 订单：实现 `OrderManagerInterface`，提供 `order.manager`，发布 `order.created/status_changed/paid/refunded`。
- 支付：实现 `PaymentGatewayInterface`，提供带 Provider ID 的 `payment.gateway`，使用 Webhook 路由。
- 邮件/短信：实现 `NotificationChannelInterface`，发送工作放入 Job。
- 论坛/积分/抽奖：依赖 `member.identity`；积分实现 `points.manager`；用领域 Event 解耦。
- 导入导出/采集/转换：实现对应多提供者服务；大文件和网络采集必须分片。

## 11. 兼容性

Plugin API 采用语义化版本。同一主版本只增加兼容方法。插件升级时新增依赖、路由、权限或服务会重新验证；数据库迁移失败不会切换激活版本。安装新版本不会提前改变正在运行的旧 Manifest。后台和 `php shopagg plugin:rollback <id> [version]` 可原子切换回已保留的代码版本；回滚不会反向删除已执行的数据库迁移，因此插件迁移必须保持向前兼容。卸载默认保留数据，只有后台“永久清除”才删除插件表和设置。
